## 1. 과제 소개

🧑‍⚖️ 이번 과제가 무엇인지 소개해 주세요.

🙋 라이브러리 없이 HTML, CSS, JavaScript만으로 반응형 포트폴리오 사이트를 만들었습니다. 다크 모드, 햄버거 메뉴, 폼 검증, GitHub API 연동이 있고 GitHub Pages로 배포했습니다. 핵심은 "이벤트 → 상태 변경 → 화면 업데이트" 흐름을 직접 만들어 보는 것이었습니다.

🧑‍⚖️ ↳ 왜 React 전에 이걸 먼저 하나요?

🙋 React가 대신해 주는 일이 바로 이것이기 때문입니다. 저는 `projectsState`를 바꾸고 `renderProjects()`로 다시 그렸는데, React에서는 `setState`를 부르면 다시 그리는 걸 React가 해 줍니다. 직접 해 봐야 React가 무엇을 자동화하는지 압니다.

🧑‍⚖️ ↳ 배포 주소는요?

🙋 https://0802222.github.io/Codyssey-B1-1-MyProfile/ 입니다. 저장소의 `main` 브랜치 루트를 GitHub Pages로 배포했습니다.

## 2. 핵심 개념

### 시맨틱 태그

🧑‍⚖️ 시맨틱 태그를 왜 썼나요?

🙋 태그 이름이 역할을 말해 주기 때문입니다. 스크린 리더가 "탐색 메뉴", "본문"을 구분해 읽고, 검색 엔진도 본문을 알아봅니다. 코드를 읽는 사람도 `div`만 있을 때보다 구조를 빨리 파악합니다.

🧑‍⚖️ ↳ `section`과 `article`은 어떤 기준으로 나눴나요?

🙋 `section`은 제목을 가진 주제 묶음이라 About, Skills, Projects, Contact에 썼습니다. `article`은 떼어 내도 혼자 의미가 통하는 내용이라 스킬 카드와 프로젝트 카드에 썼습니다.

🧑‍⚖️ ↳ `label`의 `for`는 왜 맞췄나요?

🙋 `for="email"`과 `id="email"`이 연결되면 라벨을 눌러도 입력칸에 포커스가 가고, 스크린 리더가 입력칸을 "이메일"이라고 읽어 줍니다.

### Flexbox와 Grid

🧑‍⚖️ Flexbox와 Grid 차이는요?

🙋 Flexbox는 한 방향으로 늘어놓는 1차원 배치, Grid는 행과 열을 함께 맞추는 2차원 배치입니다. 그래서 네비게이션처럼 한 줄 정렬은 Flexbox, 카드 목록처럼 바둑판 배치는 Grid를 썼습니다.

🧑‍⚖️ ↳ `repeat(auto-fit, minmax(260px, 1fr))`를 풀어서 말해 보세요.

🙋 "카드 최소 폭 260px을 지키면서 들어갈 수 있는 만큼 열을 만들고, 남는 공간은 똑같이 나눠라"입니다. 그래서 미디어 쿼리 없이 375px에서는 1열, 800px에서는 2열, 1280px에서는 3열이 됩니다.

🧑‍⚖️ ↳ 스킬 태그 목록은 왜 Grid가 아니라 Flexbox인가요?

🙋 태그 길이가 제각각이라 칸을 맞출 필요가 없고, 한 줄로 늘어놓다가 넘치면 줄바꿈만 하면 되기 때문입니다. `flex-wrap: wrap`으로 처리했습니다.

### 반응형

🧑‍⚖️ 모바일 퍼스트가 무슨 뜻인가요?

🙋 기본 CSS를 모바일용으로 쓰고, `@media (min-width: 768px)`처럼 넓은 화면용 스타일을 덧붙이는 방식입니다. 기본 상태에서 메뉴는 숨기고 햄버거 버튼을 보여 주고, 768px부터 메뉴를 가로로 펼칩니다.

🧑‍⚖️ ↳ 브레이크포인트는요?

🙋 768px에서 태블릿, 1024px에서 데스크톱입니다. 768px에서 햄버거가 사라지고 Skills가 2열, 1024px에서 Skills가 3열이 됩니다.

### DOM과 이벤트

🧑‍⚖️ `querySelector`와 `addEventListener` 흐름을 햄버거 메뉴로 설명해 주세요.

🙋 먼저 `querySelector('.nav__toggle')`로 버튼을 찾고, `addEventListener('click', ...)`로 클릭 시 실행할 함수를 등록합니다. 그 함수에서 `navMenu.classList.toggle('active')`로 클래스를 붙였다 뗐다 하고, CSS가 `.nav__menu.active`일 때만 메뉴를 보여 줍니다.

🧑‍⚖️ ↳ `onclick` 속성은 왜 안 썼나요?

🙋 HTML에 동작 코드가 섞이고, 한 요소에 함수를 하나만 걸 수 있기 때문입니다. `addEventListener`는 구조와 동작을 분리하고 여러 함수를 걸 수 있습니다.

🧑‍⚖️ ↳ `preventDefault()`는 어디에 썼나요?

🙋 두 곳입니다. 앵커 링크 클릭에서는 순간 이동을 막고 `scrollIntoView({ behavior: 'smooth' })`로 부드럽게 이동시켰고, 폼 제출에서는 페이지 새로고침을 막고 JS로 검증했습니다.

🧑‍⚖️ ↳ `defer`는 왜 붙였나요?

🙋 스크립트를 `<head>`에 두면 HTML이 아직 없어서 `querySelector`가 `null`을 돌려줍니다. `defer`는 HTML을 다 읽은 뒤에 적힌 순서대로 실행해 줘서 요소를 항상 찾을 수 있습니다.

### ES6+ 문법

🧑‍⚖️ 구조분해 할당은 어디에 썼나요?

🙋 GitHub 응답에서 필요한 값만 꺼낼 때 썼습니다. `toProject = ({ name, description, html_url, ... }) => ({ ... })`처럼 매개변수에서 바로 꺼내서, 80개 넘는 값 중 6개만 담은 새 객체를 만듭니다.

🧑‍⚖️ ↳ `map`과 `forEach` 차이는요?

🙋 `map`은 각 요소를 바꾼 **새 배열**을 돌려주고, `forEach`는 돌려주는 값 없이 순회만 합니다. 그래서 카드 HTML을 만들 때는 `map`, 링크마다 리스너를 거는 것처럼 결과가 필요 없을 때는 `forEach`를 썼습니다.

🧑‍⚖️ ↳ 화살표 함수를 쓰면 뭐가 좋나요?

🙋 콜백을 짧게 쓸 수 있습니다. `data.filter(({ fork }) => !fork)`처럼 한 줄로 조건을 표현할 수 있어 "무엇을 거르는지"가 바로 보입니다.

### 비동기

🧑‍⚖️ `fetch`와 `async/await`를 설명해 주세요.

🙋 `fetch`는 요청을 보내고 결과를 나중에 주는 Promise를 돌려줍니다. `await`를 붙이면 결과가 올 때까지 그 함수 안에서만 기다려서, 코드를 위에서 아래로 읽듯 쓸 수 있습니다. 기다리는 동안에도 스크롤이나 다크 모드는 그대로 동작합니다.

🧑‍⚖️ ↳ 404가 오면 `catch`로 가나요?

🙋 아니요. `fetch`는 응답만 오면 404, 403이어도 성공으로 봅니다. 그래서 `response.ok`가 `false`면 제가 직접 `throw`해서 `catch`로 보냅니다. `fetch` 자체가 실패하는 건 네트워크가 끊겼을 때이고, 그때는 `TypeError`가 납니다.

🧑‍⚖️ ↳ 로딩 / 성공 / 실패를 UI로 어떻게 표현했나요?

🙋 `projectsState.status`를 `loading`, `success`, `empty`, `error` 중 하나로 두고, `renderProjects()`가 상태별로 다른 HTML을 그립니다. 로딩은 스피너와 "로딩 중...", 성공은 카드, 빈 상태는 "표시할 프로젝트가 없습니다", 에러는 원인 문구와 다시 시도 버튼입니다.

### 상태 → 렌더링

🧑‍⚖️ "이벤트 → 상태 변경 → DOM 업데이트"를 예로 들어 주세요.

🙋 Java 필터를 누르면 클릭 이벤트에서 `setProjectsState({ selectedLanguage: 'Java' })`만 호출합니다. 그 안에서 상태를 바꾸고 `renderProjects()`를 부르면, 상태를 보고 필터 버튼과 카드 목록을 다시 그립니다. 이벤트 처리 코드는 화면을 직접 건드리지 않습니다.

🧑‍⚖️ ↳ 그런 흐름이 몇 개 있나요?

🙋 네 개입니다. 다크 모드(`currentTheme`), API 요청(`projectsState.status`), 폼 입력(`formErrors`), 언어 필터(`selectedLanguage`)입니다.

🧑‍⚖️ ↳ 이렇게 나누면 뭐가 좋은가요?

🙋 화면이 어떻게 보일지는 상태만 보면 알 수 있습니다. 여러 곳에서 DOM을 직접 고치면 "상태와 화면이 다른" 버그가 생기기 쉬운데, 그리는 곳이 하나라 그런 일이 없습니다.

### Intersection Observer

🧑‍⚖️ 스크롤 애니메이션은 어떻게 만들었나요?

🙋 Intersection Observer로 `.reveal` 요소를 감시하다가 20% 이상 보이면 `.is-visible` 클래스를 붙입니다. 움직임 자체는 CSS `transition`이 처리하고, 한 번 나타난 요소는 `unobserve`로 감시를 끝냅니다.

🧑‍⚖️ ↳ `scroll` 이벤트로 직접 하면 안 되나요?

🙋 됩니다. 하지만 스크롤할 때마다 모든 요소의 위치를 계산해야 해서 비효율적입니다. Observer는 브라우저가 보이는 비율이 기준을 넘을 때만 알려 줍니다.

🧑‍⚖️ ↳ 프로젝트 카드 그리드에는 왜 안 걸었나요?

🙋 모바일에서 카드 38개 높이가 화면의 몇 배라, 그리드 전체의 20%가 한 화면에 보이는 순간이 오지 않을 수 있습니다. 그러면 영영 안 보이게 되니 제목 영역에만 걸었습니다.

## 3. 최종 결과물 요구사항

🧑‍⚖️ 요구사항 다섯 가지를 어떻게 충족했는지 짧게 말해 주세요.

🙋
- 반응형 : 모바일 퍼스트 + 768px, 1024px, 6개 섹션 모두 있음
- 인터랙티브 UI : 다크 모드, 햄버거, 부드러운 스크롤, 스크롤 애니메이션, 폼 검증
- 외부 API : GitHub 저장소를 카드로, 로딩 / 에러 / 빈 상태 UI
- 상태 유지 : 다크 모드를 로컬스토리지 `theme` 키에 저장
- 배포 : GitHub Pages

🧑‍⚖️ ↳ 기준값들은 얼마로 정했나요?

🙋 헤더 배경은 60px, 맨 위로 버튼은 300px, 스크롤 애니메이션 threshold는 0.2입니다. 과제 권장값 그대로이고 `nav.js`, `animation.js` 맨 위 상수로 두었고 README에도 적었습니다.

🧑‍⚖️ ↳ 새로고침 후 다크 모드가 유지되는 걸 어떻게 확인하나요?

🙋 토글을 누르고 개발자 도구 Application → Local Storage를 보면 `theme: dark`가 있습니다. 새로고침하면 `getInitialTheme()`이 이 값을 먼저 읽어서 다크로 시작합니다.

## 4. 프로젝트 구조

🧑‍⚖️ 폴더 구조를 설명해 주세요.

🙋 `index.html` 하나, 스타일은 `css/style.css`, 스크립트는 `js/`에 기능별 5개 파일, 이미지는 `images/`에 있습니다. JS는 `theme`, `nav`, `animation`, `form`, `projects`로 나눠서 파일 이름만 보고 기능을 찾을 수 있게 했습니다.

🧑‍⚖️ ↳ 파일이 다섯 개인데 변수 이름이 겹치면요?

🙋 `defer` 일반 스크립트는 맨 위 `const`가 전역에서 공유되기 때문에 이름이 겹치면 에러가 납니다. 그래서 `navMenu`, `projectsState`, `formErrors`처럼 기능 이름을 앞에 붙여 겹치지 않게 했습니다.

🧑‍⚖️ ↳ CSS는 어떻게 정리했나요?

🙋 맨 위에 변수, 그다음 기본 스타일, 섹션별 스타일, 마지막에 768px, 1024px 미디어 쿼리 순서입니다. 모바일 퍼스트라 미디어 쿼리가 파일 끝에 모여 있습니다.

## 5. 기능

🧑‍⚖️ 햄버거 메뉴를 시연하면서 설명해 주세요.

🙋 375px에서 버튼을 누르면 `classList.toggle('active')`로 메뉴와 버튼에 `active`가 붙어 메뉴가 열리고 버튼이 X로 바뀝니다. 다시 누르면 닫힙니다. 메뉴 링크를 누르면 섹션으로 이동하면서 `closeMenu()`가 메뉴를 닫습니다.

🧑‍⚖️ ↳ `aria-expanded`는 왜 바꾸나요?

🙋 화면을 못 보는 사용자에게 메뉴가 열렸는지 닫혔는지 알려 주기 위해서입니다. 스크린 리더가 "확장됨 / 축소됨"으로 읽어 줍니다.

🧑‍⚖️ 다크 모드는요?

🙋 토글을 누르면 `currentTheme`을 바꾸고 로컬스토리지에 저장한 뒤 `renderTheme()`이 `<html data-theme="dark">`로 바꿉니다. CSS는 변수만 쓰고 있어서 `[data-theme="dark"]`의 변수 값으로 페이지 전체 색이 바뀝니다.

🧑‍⚖️ ↳ 보너스는 뭘 했나요?

🙋 세 가지입니다. 언어별 필터, Hero 타이핑 효과, 시스템 다크 모드 감지입니다. 폼 실제 전송은 하지 않았습니다.

🧑‍⚖️ ↳ 시스템 다크 모드 감지는 어떻게 동작하나요?

🙋 저장값이 없을 때만 `matchMedia('(prefers-color-scheme: dark)')` 결과를 따릅니다. 한 번이라도 직접 고르면 저장값이 우선합니다. 고른 적이 없으면 운영체제 설정을 바꿀 때 `change` 이벤트로 바로 따라갑니다.

🧑‍⚖️ 폼 검증은 언제 실행되나요?

🙋 두 번입니다. 글자를 칠 때마다 `input` 이벤트로 그 필드만 검사하고, 제출할 때 `submit` 이벤트로 세 필드를 모두 검사합니다. 하나라도 틀리면 첫 번째 틀린 칸에 포커스를 줍니다.

🧑‍⚖️ ↳ 이메일 정규식을 읽어 보세요.

🙋 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`는 "공백과 @가 아닌 글자 1개 이상, @, 글자들, 점, 글자들"입니다. `test@`는 @ 뒤가 비어서 실패, `test@example.com`은 통과합니다.

🧑‍⚖️ ↳ `novalidate`는 왜 붙였나요?

🙋 `type="email"`이 있으면 브라우저가 자기 말풍선을 먼저 띄웁니다. 과제 요구대로 입력칸 아래에 제 에러 문구를 보여 주려고 브라우저 기본 검사를 껐습니다.

## 6. 명령 처리 흐름

🧑‍⚖️ 페이지를 열면 어떤 순서로 실행되나요?

🙋 HTML을 다 읽은 뒤 `defer` 스크립트가 순서대로 실행됩니다. `theme.js`가 테마를 정하고, `nav.js`가 리스너를 걸고, `animation.js`가 관찰과 타이핑을 시작하고, `form.js`가 폼 리스너를 걸고, 마지막으로 `projects.js`가 로딩 상태를 그린 뒤 API를 호출합니다.

🧑‍⚖️ ↳ 필터 버튼은 다시 그려지는데 리스너는 어떻게 유지되나요?

🙋 버튼이 아니라 부모 `.projects__filters`에 리스너를 한 번 걸었습니다. 클릭 이벤트는 버블링으로 부모까지 올라오니까 `event.target.closest('.filter-btn')`으로 어떤 버튼인지 찾습니다. 이벤트 위임입니다. 다시 시도 버튼도 같은 방식입니다.

🧑‍⚖️ ↳ 필터를 누르면 API를 다시 부르나요?

🙋 아니요. 이미 받은 `repos`에서 `filter`로 거르기만 합니다. 레이트 리밋도 아끼고 즉시 바뀝니다.

## 7. 예외 처리

🧑‍⚖️ GitHub API 레이트 리밋에 걸리면요?

🙋 인증 없이 시간당 60회를 넘기면 403이 옵니다. `response.ok`가 `false`라 `getErrorMessage(403)`의 "요청 한도를 초과했습니다" 문구로 에러를 던지고, 에러 상태 화면에 다시 시도 버튼과 함께 보여 줍니다.

🧑‍⚖️ ↳ 그걸 실제로 어떻게 테스트했나요?

🙋 60번을 부르는 대신 콘솔에서 `window.fetch`를 403을 돌려주는 함수로 바꾸고 다시 시도를 눌렀습니다. 404는 `?user=없는아이디`, 빈 상태는 저장소가 0개인 `?user=ghost`, 네트워크 실패는 개발자 도구 Offline으로 확인했습니다.

🧑‍⚖️ ↳ `innerHTML`은 위험하지 않나요?

🙋 외부 문자열을 그대로 넣으면 그 안의 태그가 실행될 수 있습니다. 그래서 저장소 이름, 설명, 언어는 `escapeHTML()`로 `<`를 `&lt;`처럼 바꾼 뒤 넣습니다. 폼 에러 문구처럼 글자만 바꿀 때는 `textContent`를 썼습니다.

🧑‍⚖️ ↳ 로컬스토리지가 막혀 있으면요?

🙋 사생활 보호 모드 등에서는 접근할 때 예외가 날 수 있어서 `try/catch`로 감쌌습니다. 저장만 실패하고 테마 전환은 그대로 됩니다.

🧑‍⚖️ ↳ 저장소 설명이 비어 있으면요?

🙋 GitHub는 `null`을 줍니다. `toProject()`에서 설명은 "설명이 없습니다.", 언어는 "기타"로 바꿔서 화면에 `null`이 찍히지 않게 했습니다.

## 8. 제약 사항

🧑‍⚖️ 외부 라이브러리를 정말 안 썼나요?

🙋 네. 허용된 Google Fonts(Noto Sans KR)만 썼고, 아이콘은 이모지와 CSS로 만든 햄버거 막대입니다.

🧑‍⚖️ ↳ `var`, `onclick`, 인라인 스타일이 없는지 어떻게 확인하나요?

🙋 `grep -rn "var " js/`, `grep -n "onclick"`, `grep -n 'style="'` 세 명령 모두 결과가 0건입니다. 스타일을 바꿀 때도 `style` 속성 대신 `classList`로 클래스를 붙였다 뗍니다.

🧑‍⚖️ ↳ 제출물은요?

🙋 저장소 URL, 배포 URL, 그리고 README 시연 섹션에 데스크톱, 모바일, 다크 모드 스크린샷이 있습니다.

## 9. 꼬리 질문

🧑‍⚖️ `classList.toggle('active')`의 반환값은 무엇인가요?

🙋 토글한 뒤에 클래스가 있으면 `true`, 없으면 `false`입니다. 그 값을 `isOpen`으로 받아 햄버거 버튼과 `aria-expanded`를 같은 상태로 맞췄습니다.

🧑‍⚖️ 섹션으로 이동할 때 고정 헤더에 제목이 가려지지 않는 이유는요?

🙋 CSS에서 `section`에 `scroll-margin-top: var(--header-height)`를 줬습니다. 스크롤 목적지를 헤더 높이 64px만큼 내려 줘서 제목이 헤더 바로 아래에 옵니다.

🧑‍⚖️ 상태 확인용 `?user=` 파라미터는 어떻게 읽나요?

🙋 `new URLSearchParams(window.location.search).get('user')`로 읽고, 없으면 기본값 `0802222`를 씁니다.

🧑‍⚖️ `join('')`은 왜 붙이나요?

🙋 `map`의 결과는 문자열 배열입니다. 그대로 `innerHTML`에 넣으면 쉼표가 끼어서 화면에 찍히니까 빈 문자열로 이어 붙여 하나의 HTML 문자열로 만듭니다. DOM도 한 번만 바뀝니다.

🧑‍⚖️ 다크 모드에서 새로고침하면 잠깐 밝게 깜빡일 수 있지 않나요?

🙋 네, `defer`라 HTML을 그린 뒤에 테마를 정하기 때문에 아주 짧게 라이트로 보일 수 있습니다. 막으려면 `<head>`에서 테마만 먼저 정하는 작은 스크립트를 `defer` 없이 실행하면 됩니다. 이번에는 "모든 JS를 `defer`로 연결"이라는 요구를 지키는 쪽을 택했습니다.

🧑‍⚖️ `Object.assign(projectsState, nextState)`는 무슨 일을 하나요?

🙋 `nextState`에 있는 키만 `projectsState`에 덮어씁니다. 그래서 `{ selectedLanguage: 'Java' }`만 넘겨도 `status`나 `repos`는 그대로 남습니다. React의 `setState`가 일부만 넘겨도 되는 것과 비슷합니다.

🧑‍⚖️ 타이핑 효과에서 `setInterval` 대신 `setTimeout`을 쓴 이유는요?

🙋 다 쓰면 멈춰야 하는데, `setTimeout`은 다음 글자가 남았을 때만 다음 호출을 예약하니 따로 멈추는 코드가 필요 없습니다. `setInterval`이면 `clearInterval`을 챙겨야 합니다.

🧑‍⚖️ 포크 저장소는 왜 뺐나요?

🙋 포크는 남의 저장소를 복사한 것이라 제 작업을 보여 주는 포트폴리오에 맞지 않습니다. `filter(({ fork }) => !fork)` 한 줄로 뺐고, 43개 중 5개가 빠져 38개가 보입니다.
